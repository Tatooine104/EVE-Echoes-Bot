# 📋 ТЕХНИЧЕСКОЕ МЕМО ПО АРХИТЕКТУРЕ И ТЕКУЩЕМУ СТАТУСУ ПРОЕКТА `EVEEchoesBot`

**Контекст сессии:** Написано для ИИ-коллеги по разработке. Проект переведен на .NET 9+ / C# 13, задействован новый нативный тип блокировок `System.Threading.Lock`. В качестве ядра автоматизации используется реактивное Дерево Поведения (Behavior Tree). Была проведена глубокая отладка асинхронного планировщика задач и многопоточного взаимодействия с бэкендом Minimal API Kestrel.

---

### 1. ТЕКУЩИЙ СТАТУС И УСПЕХИ (ЧТО УЖЕ ИДЕАЛЬНО РАБОТАЕТ)
* **Параллельные Воркеры ожили**: Полностью ликвидированы каскадные дедлоки и падения тасок по `A task was canceled`. Боты успешно запускаются параллельно в `RunLoopAsync` и координируют свои действия.
* **Сценарий `LowMiner` (Майнер)**: Полностью ожил и встал на рельсы! Бот успешно проходит проверки на станции, проверяет трюм, заходит в монолитный конвейер, прожимает ADB-кликером **Андок (Undock)** и стабильно улетает из дока в открытый космос копать белты.
* **Сценарий `LocalWatcher` (Наблюдатель)**: Полностью ожил! Бот стабильно сидит на станции в безопасности, не кликает вхолостую и выдает ровный, красивый ежесекундный пульс планового анализа экрана и мониторинга локал-чата.
* **Макрос Планетарки**: Отрабатывает идеально от начала до конца. Находит иконки, заходит в интерфейс, прожимает перезапуск таймеров заводов, подтверждает диалоги и плавно закрывает окна без зависаний.

### 2. КРИТИЧЕСКИЕ ИЗМЕНЕНИЯ В АРХИТЕКТУРЕ (ЧТО МЫ ПОЧИНИЛИ)

#### А. Графический конвейер и семафоры (`Tools.CaptureWindowAsync`)
* **Проблема**: Запросы скриншотов из веб-панели (HTTP-потоки Kestrel) параллельно с тактами дерева лезли в WinAPI (`BitBlt`/`GetDC`). Это вызывало жесткий конфликт GDI на уровне ядра Windows, намертво вешая фоновые потоки воркеров CLR прямо перед вызовами OpenCV.
* **Решение**: Метод захвата переведен на асинхронные рельсы `public static async Task<Mat?> CaptureWindowAsync(...)`. Управление семафором `bot.AccountGdiSemaphore` инкапсулировано строго внутри него через `await WaitAsync(token)`. Все внешние HTTP-эндпоинты в `Program.cs` (`MapPost`/`MapGet` для снимков и регионов) переведены на вызов этой асинхронной версии с обязательной передачей персонального семафора бота и токена отмены.

#### Б. Избавление от "Self-Deadlock" на локах .NET 9 (`CheckIfPlanetMiningTime`)
* **Проблема**: Проверка времени планетарки была асинхронным узлом дерева. На каждом тике она вызывала `Logger.Log`, который запрашивал свойства `bot.EVESystem` и `bot.EVEShip`. Внутри геттеров этих свойств стоял повторный `lock (_taskLock)`. Новый тип `System.Threading.Lock` в .NET 9 при синхронных тасках расценивал это как конфликт планировщика и намертво блокировал поток сам на себе.
* **Решение**: Метод проверки времени полностью переведен в **плоский синхронный вид** `private static NodeStatus CheckIfPlanetMiningTime(ActiveBotAccount bot)`. Из него полностью вырезан внутренний `lock`, а обращение к логам переведено на чтение сырых полей с подчёркиванием (`bot._eveSystem`, `bot._eveShip`). В дереве он теперь упакован в чистый синхронный `Task.FromResult`:
  ```csharp
  new ActionNode("Check Planet Mining Conditions", (b, _) => Task.FromResult(CheckIfPlanetMiningTime(b)))
  ```

#### В. Выпрямление Деревьев и Сброс Флагов Состояний
* **Проблема**: Дерево зацикливалось в мирной петле паники на станции. При подтверждении дока `bot.CurrentTask` оставался равен `AccountTask.GoToStation`, из-за чего Selector бесконечно крутил ветку эвакуации, не пуская поток к мирному обслуживанию.
* **Решение**: В метод `CheckIsDockedAsync` встроен жесткий сброс: если кнопка андока на экране и стейт равен `GoToStation`, бот принудительно переключает `bot.CurrentTask = AccountTask.CheckSecurity`. Блокировка мгновенно снимается. Узлы `SequenceNode` и `SelectorNode` в `BehaviorNode.cs` были временно расширены отладочным трейсером `[BT-TRACE]` со сквозным вызовом `.ConfigureAwait(false)`.

#### Г. Оптимизация Файлового Логгера (Debug vs Release)
* **Проблема**: В логгер был внедрен виснущий цикл `while`, обрезавший потокобезопасную очередь логов Kestrel, что вешало процессор при конкурентном чтении.
* **Решение**: Цикл `while` заменен на атомарный одиночный сброс `if (_webLogsCache.Count > 15)`. Внутрь блока записи в CSV внедрена условная компиляция:
  ```csharp
  #if DEBUG
      bool isAllowWriteToFile = true; // Пишем абсолютно всё, включая [BT-TRACE]
  #else
      bool isAllowWriteToFile = type is LogType.Warning or LogType.Error or LogType.Info; // Только важное
  #endif
  ```

### 3. СЛЕДУЮЩИЕ ШАГИ ПРИ ВОЗОБНОВЛЕНИИ СЕССИИ (КУДА СМОТРЕТЬ ДАЛЬШЕ)
Когда пользователь вернется, необходимо продолжить построчный аудит кодовой базы, двигаясь из дока станции в глубокий космос:
1. **Проверить полетный блок космоса** в `BuildMinerTree()`: взять под построчный контроль методы **`CheckIsNotInMiningZoneAsync`** и **`SelectAsteroidBeltAsync`**. Проверить, как там устроена навигация.
2. **Проверить блок активной добычи**: отаудировать методы **`TargetAsteroidAsync`** и **`ActivateLasersAsync`**. Исключить скрытые блокировки потоков при вызове ADB-кликера и поиске крестиков/полосок таргета через OpenCV.
3. **Почистить логи**: если стабильность подтверждена, можно убрать или закомментировать шумные отладочные префиксы `[BT-TRACE]` в `BehaviorNode.cs`, чтобы разгрузить панель.
